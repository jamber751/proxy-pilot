# Минимальный ProxyPilot — результат и проверка

6 сентября 2026. Этот документ описывает новую реализацию; предыдущий `ux-audit-2026-09-06.md` сохраняет историю выявленных проблем.

## Дополнение: окно у иконки, настройки и маршрут

После обратной связи со скриншотами WARP отдельное центрированное окно заменено на нативный `NSPopover`, привязанный к кнопке в меню-баре. Использован [API позиционирования Apple](https://developer.apple.com/documentation/appkit/nspopover/show(relativeto:of:preferrededge:)). Повторное нажатие на иконку закрывает popover; установлен режим `.transient` для закрытия при взаимодействии снаружи. Шестерёнка открывает внутри того же окна автонастройку и ручное поле адреса; стрелка возвращает на главный экран.

Строка «Маршрут» показывает «Напрямую», «SOCKS5» или «HTTP» по `running` реального процесса моста и состоянию системного прокси, не по сохранённому предпочтению. При неполном/неизвестном состоянии — «Не определён». Подписи относятся к ProxyPilot, а не ко всем пакетам Mac: независимые VPN/прокси и приложения, игнорирующие системный прокси, не проверяются.

Проверки дополнения: universal-сборка успешна; 12 тестов проходят, включая компиляцию реального Swift-моделя и 9 вариантов маршрута (SOCKS5/HTTP/direct/off/ошибочные состояния). Установленная версия обновлена; предыдущее приложение сохранено в `/private/tmp/proxypilot-before-popover.ce1uiz/ProxyPilot.app`. Реальный `app-state` перед и после обновления: enabled=true, running=direct, system_proxy=true. Настройки сети в этой итерации не менялись.

UI-проверка дополнения: первые попытки обращения к `NSPopover` дали `timeoutReached` / `noWindowsAvailable`, но после финального запуска окно успешно получено. На реальном приложении снят popover со стрелочкой и маршрутом «Напрямую», проверены клик по шестерёнке, настройки в том же окне, неактивная кнопка при пустом адресе, активация кнопки для `http://proxy.example:3128` и возврат на главный экран. Тестовый адрес очищен без сохранения. Скриншоты: `app/build/screenshots/popover-main.png` и `popover-settings.png`. Закрытие по клику снаружи, повторный клик именно по иконке и размещение на нескольких мониторах отдельно не пройдены. Ниже сохранены проверки предыдущего оконного интерфейса.

## Интерфейс

### Дополнение: список настроенных прокси и отдельные поля

В настройках теперь отображаются существующие SOCKS5/HTTP-адреса с отметками «Настроен» / «Используется» (последняя — по текущему режиму работающего моста). Кнопка «+» открывает форму IP/хост + порт + сегментированный выбор SOCKS5/HTTP; URL-схему вводить не нужно. Клик по записи заполняет поля для редактирования. Сохранение проверяет доступность сервера и подключает выбранный протокол, затем возвращает список. Текущая модель хранит по одному адресу каждого протокола; при замене адреса показано предупреждение. Другой протокол и OFFICE_GATEWAYS больше не очищаются при ручном сохранении.

CLI `app-state` возвращает адреса с JSON-экранированием. Проверены 24 теста: сохранение второго протокола, выбор именно сохраняемого протокола, экранирование, валидация раздельных полей и подстановка адреса. На установленной версии просмотрены оба реальных адреса, плюс, переключение HTTP/SOCKS5, блокировка порта 65536 и активация кнопки для корректного порта. Сохранение тестового адреса не выполнялось; пользовательский config побайтово совпал с резервной копией. Дальнейшие клики прекращены, поскольку пользователь начал взаимодействовать с окном. Скриншоты: `app/build/screenshots/proxy-list.png`, `proxy-form.png`. Предыдущая сборка и config: `/private/tmp/proxypilot-before-proxy-list.Yv976h/`.

### Дополнение: выбор маршрута на главном экране

Визуальное обновление: системное выпадающее меню заменено экраном выбора внутри popover. Четыре компактные строки с иконками, пояснениями, зелёной отметкой сохранённого выбора и hover-подсветкой. На главном экране — карточка фактического маршрута с меткой «Авто», когда выбран автоматический режим. Под ошибки и процесс применения выделено постоянное место, чтобы строки не смещались. На установленной версии проверены открытие, выбранное состояние и возврат; скриншот — `app/build/screenshots/styled-route-picker.png`. Сборка и 21 регрессионный тест прошли. Сетевые команды при визуальной проверке не выполнялись.

Строка «Маршрут» стала раскрывающимся меню: Авто / Напрямую / SOCKS5 / HTTP. Галочка показывает сохранённый выбор, основной текст — фактически работающий маршрут. Ненастроенный протокол недоступен. Выбор при выключенном приложении сохраняется без включения; кнопка питания использует сохранённый выбор. При недоступности сервера текущий маршрут не меняется; при ошибке запуска выполняется попытка восстановления предыдущего выбора. Существующий автоматический fallback ручного маршрута на direct при последующей недоступности сервера явно подписан в интерфейсе.

Проверено 21 тестом, включая отказ недоступного/ненастроенного маршрута, сохранение при off, включение выбранного режима и откат после ошибки. На реальном установленном приложении кликами проверены меню с четырьмя пунктами и галочкой, выбор direct, off → on с сохранением direct, отказ SOCKS5 и HTTP в текущей сети без смены рабочего direct, возврат к исходному auto. Финальное состояние: enabled=true, selected=auto, running=direct. HTTP и SOCKS5h запросы через локальный мост дали HTTP 200. Внешние SOCKS5/HTTP-серверы именно в этой итерации недоступны; успешное ручное переключение на них не выдаётся за проверенный результат. Резервная копия установленного приложения: `/private/tmp/proxypilot-before-route-menu.25SNAx/ProxyPilot.app`.

### Дополнение: локальный SOCKS5 для Telegram

Локальный мост теперь использует [GOST auto handler](https://gost.run/en/reference/handlers/auto/): HTTP CONNECT и SOCKS5 на одном адресе `127.0.0.1:3129` (либо настроенном `BRIDGE_PORT`). Оба входных протокола используют одну цепочку апстрима, DNS и bypass. Дополнительный порт и LAN-доступ не открывались. При обновлении `ensure` один раз перезапускает старый HTTP-only мост; последующие проверки остаются идемпотентными.

Проверено: 16 тестов, включая реальные изолированные GOST-процессы и HTTP/SOCKS5-клиентов в direct, HTTP-upstream, SOCKS5-upstream. В тестах отключение upstream делает запрос неуспешным: цепочка действительно используется, а не обходится напрямую. На установленной версии оба HTTPS-запроса к example.com через HTTP и SOCKS5h дали HTTP 200; текущий фактический апстрим на момент этой проверки — SOCKS5. `lsof` подтверждает слушатель только на `127.0.0.1:3129`. Пользовательский config побайтово не изменился. Приложение обновлено; резервная копия — `/private/tmp/proxypilot-before-socks5.ah5za0/`.

Telegram: тип SOCKS5, сервер `127.0.0.1`, порт `3129`, логин и пароль пустые. Настройки самого Telegram не менялись; его сообщения/медиа/звонки в этой итерации не проверялись. UDP relay не включён. При выключении ProxyPilot оставшийся мост идёт напрямую; при полностью остановленном мосте нужно выключить прокси в Telegram или запустить ProxyPilot.

Референс: [Opera VPN в Mobbin](https://mobbin.com/screens/d535f3b2-da66-427c-92d7-b679c7dede17) — ясный статус и одно действие отключения. Для macOS реализовано отдельное компактное окно, открываемое из меню-бара. Тёмная и светлая темы следуют оформлению системы.

Основной сценарий: «Найти автоматически» → «Прокси включён» → «Выключить» / «Включить». Если поиск не помог, доступно одно поле с адресом `socks5://host:port` или `http://host:port`. Повторная настройка открывается через «Подключение». Поле не принимает адреса с авторизацией и IPv6; кнопка неактивна при неверном формате.

Удалены старые SettingsView, ConfigStore, меню выбора режимов, UI сетевого профиля/VPN, бенчмарки и их обработчики. Старые CLI-команды и ранее установленные VPN/net-демоны сохранены для совместимости; кнопка питания ими не управляет.

## Исправленная логика

- Команды и фоновое обновление выполняются в одной последовательной очереди.
- Ошибки CLI и коды завершения учитываются; включение подтверждается мостом и обоими системными прокси, HTTP и HTTPS.
- После ошибки запуска флаг включения откатывается. Отказ macOS менять сетевые настройки возвращает ошибку.
- Настройка повторно читает найденные адреса до включения и сохраняет посторонние ключи конфига.
- Выключение убирает собственные системные прокси; работающий локальный мост переводится в прямой режим для уже открытых терминалов. Остановленный мост при off не перезапускается.
- Новые терминалы при off не получают proxy-переменные ProxyPilot; переменные другого прокси не удаляются.
- Выход сначала выполняет выключение и остаётся в приложении при ошибке. Уже открытые терминалы сохраняют прямое соединение через локальный мост.
- UI использует совпадающую вложенную версию CLI. Добавлен быстрый `app-state`, не опрашивающий VPN.

## Автоматические проверки

`python3 -m unittest discover -s tests -v`: 11 успешных регрессионных тестов производственных zsh-функций с изолированными системными зависимостями. Проверены откат после ошибки моста, сохранение работающего моста при отказе выключения, direct при off, отсутствие самозапуска остановленного моста, shellenv, отказ/успех системной настройки, чужой прокси, частичная настройка HTTP/HTTPS, повторный detect и валидация адресов.

Swift собран для arm64 и x86_64 с целевой macOS 11; проверена ad-hoc подпись. Синтаксис shell-скриптов и `git diff --check` проходят.

## Что не подтверждено

Текущая сеть использовала direct. Реальное подключение к офисному SOCKS5/HTTP-апстриму, автопоиск на чистой машине, reboot, смена физических сетей, sleep/wake и VoiceOver пока не пройдены. Успешный UI flow с фиктивной сетью не выдаётся за проверку этих сетевых сценариев. Автопоиск не гарантирует нахождение нестандартных адресов/портов — для них оставлено ручное поле.
