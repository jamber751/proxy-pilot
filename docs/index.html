The problem

The fast route is right there. Your tools just can't reach it.

The corporate proxy shapes traffic

In our office the HTTP proxy sat pinned near 630 KB/s while a SOCKS5 endpoint on the very same host moved 2552 KB/s. Same network, same moment, fourfold difference.

Half the toolchain can't speak SOCKS

Point Claude Code at a socks5:// address and undici answers plainly:

API Error: Unable to connect to API
(UnsupportedProxyProtocol)

So the fast route stays unused, and everything crawls through the slow one.

Measured, not claimed

A local hop costs nothing

Same 5 MB file, same minutes, one stream each. The bridge adds a loopback hop of well under a millisecond — run-to-run noise moves the number more than the hop does.

How it works

An HTTP-CONNECT bridge with a swappable exit

Clients see an ordinary HTTP proxy on 127.0.0.1:3129. Behind it, the route out is yours to change — and changing it never touches the clients.

The address never changes

Set the system proxy once. Switch between SOCKS5, the corporate proxy and direct as often as you like — Claude Code, git and the browser carry on without a restart, because nothing they hold onto moved.

auto reads the network

The route follows the physical interface's gateway, matched against your office prefixes — not "whichever upstream answers", which on a VPN from home would route you back through the office. Take the laptop home and the proxy switches itself off.

Install is one drag

The DMG carries the CLI and the bridge binary inside, universal for Intel and Apple Silicon. No Homebrew, no terminal, no cloning a repo to get a working menu bar icon.

A menu bar app that shows the truth

The icon carries the active route. The menu carries live reachability dots for each upstream, so you know a route is dead before you pick it — and a Find on network button that discovers proxies for you. Settings (⌘,) edits addresses, bridge port and office prefixes.

The CLI is the engine, not an afterthought

Everything the app does, the terminal does too — the Settings window writes config through proxypilot set, so exactly one component knows the file format.

$ proxypilot bench
  route                   speed      time
  ──────────────────────────────────────
  direct                  —          blocked
  http   192.168.8.2:3128 630 KB/s   7.9s
  socks5 192.168.8.2:9999 2552 KB/s  2.0s

$ proxypilot auto
  ✓ route: auto → socks

Add eval "$(proxypilot shellenv)" to your .zshrc and every new shell picks up the right variables — including the lowercase http_proxy that curl insists on.

Install

Three steps, then never again

  1. Download the DMG

    Grab the latest release. It is universal and self-contained — the CLI and the bridge ship inside the app.

  2. Right-click Install.command → Open

    It copies the app to Applications, clears quarantine, offers to add it to Login Items and launches it. On first run the app finds the proxies on your network by itself and opens Settings so you can confirm them.

  3. Point the system proxy at the bridge

    System Settings → Network → Wi-Fi → Details → Proxies. Set HTTP and HTTPS to 127.0.0.1:3129 and leave SOCKS off. That address is constant, so this is the last time you open this panel.

Ad-hoc signed, not Developer ID. The first launch needs right-click → Open — macOS blocks a plain double-click on apps without a paid Apple signature. Everything after that opens normally.

Prefer the source? git clone https://github.com/jamber751/proxy-pilot.git && cd proxy-pilot && ./install.sh
