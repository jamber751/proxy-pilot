# ProxyPilot — аудит сценария «настроить → включить / выключить»

Дата: 6 сентября 2026. Объект: текущая рабочая копия, включая незакоммиченные изменения минимального меню.

## Вывод

В меню осталось одно основное действие, но готовность продукта пока не подтверждена. Выключение ломает интеграцию с терминалом, выход оставляет системный прокси на остановленном мосте, а интерфейс способен показывать «Включён» после ошибки. Предыдущий отчёт о завершённом упрощении был преждевременным: старые настройки и функции скрыты, но их реализация всё ещё присутствует.

Моя экспертная оценка соответствия заданному сценарию: **4/10**. Это оценка по коду, воспроизведениям и структуре меню, а не результат пользовательского исследования или визуального теста работающего меню.

## Дефекты и приоритеты

### P1 — выход может оставить GUI-приложения без соединения

`app/main.swift:1078`: `quit()` выполняет `CLI.run(["stop"])`. CLI `stop` останавливает мост, но не убирает macOS HTTP/HTTPS proxy. После выхода системные клиенты продолжают подключаться к порту без слушателя.

Критерий исправления: после «Выйти» система не указывает на остановленный мост; ошибка восстановления сетевых настроек видна пользователю. Проверить отдельным реальным запросом после выхода.

### P1 — «Выключить» оставляет терминал с неработающим прокси

`bin/proxypilot:778`: `cmd_shellenv` экспортирует proxy-переменные независимо от `enabled`. Обе установки добавляют вызов `shellenv` в `.zshrc`, поэтому это основной сценарий, а не редкая ручная интеграция. Уже открытые процессы также сохраняют свои переменные после остановки моста.

Воспроизведение: при `enabled=off` вывод всё равно содержит `export http_proxy='http://127.0.0.1:43129' ...`.

Критерий исправления: определить согласованную семантику отключения для терминала; проверить и новый, и уже открытый терминал. Простое условие в `shellenv` исправит только новые процессы.

### P1 — статус «Включён» не означает, что прокси работает

`bin/proxypilot:485,500`: `on` записывается до старта моста. `app/main.swift:777` рисует статус только по `enabled`; `running` и `system_proxy` не участвуют. `CLI.run` (`:95`) теряет stderr и код завершения. `togglePower` (`:948`) проверяет только наличие конфига после настройки и не показывает ошибки обычного включения/выключения.

Воспроизведение: `enable_exit=1 saved_enabled=on` при отказе запуска моста.

Критерий исправления: отдельные состояния «настраивается», «подключается», «включён», «выключается», «выключен», «ошибка»; успех только после подтверждения моста и системных настроек. При ошибке — понятная причина и повтор действия.

### P1 — системные команды сообщают об успехе при отказе

`bin/proxypilot:893`: ошибки `networksetup` подавляются. Для on неуспешный сервис пропускается, а off печатает успех без проверки результата. Если снятие прокси не удалось, `cmd_disable` всё равно остановит мост.

Воспроизведение: все вызовы `networksetup` возвращают 1, но `system_on_exit=0`, `system_off_exit=0`.

Критерий исправления: учитывать результат каждого изменённого сервиса, возвращать ошибку/частичный результат, не сообщать об успешном выключении до проверки фактического состояния.

### P1 — первый запуск использует устаревшие значения после автопоиска

`bin/proxypilot:609,749,752,774`: найденные адреса сохраняются в конфиг, затем вызывается `cmd_enable` в том же процессе. Глобальные `SOCKS_UPSTREAM`, `HTTP_UPSTREAM`, `OFFICE_GATEWAYS` не обновляются; `load_config` был вызван только при запуске скрипта.

Воспроизведение: `persisted=new.example:3128`, но `enable_uses=old.example:3128`. На чистой установке это могут быть пустые адреса. Фоновое обновление отдельным процессом может позднее скорректировать маршрут, но первая операция всё равно не атомарна.

Критерий исправления: применять именно обнаруженные значения перед включением и подтверждать итоговый маршрут.

### P2 — сценарий восстановления неполон

Если поиск ничего не нашёл, доступна повторная та же попытка без понятной инструкции для текущей сети. После появления конфига кнопка поиска исчезает; при переезде в другую сеть с другим прокси главный action вызывает только enable. При недоступном CLI меню предлагает только выход.

Критерий исправления: контекстная кнопка «Повторить настройку» в ошибке, краткая причина и следующий шаг. Она нужна в ошибочном состоянии, а не как постоянная дополнительная функция.

### P2 — конкурентные обновления могут пересекаться с действием пользователя

`app/main.swift:700`: таймер и открытие меню запускают фоновые `refresh`; `busy` проверяется до постановки работы, но уже запущенные задачи не сериализованы с `togglePower`. Возможны устаревшие состояния и пересечение ensure/disable. Это вывод из кода; гонка динамически не воспроизведена.

Критерий исправления: последовательная очередь управления, отсутствие устаревших результатов после нового действия, стабильность при быстрых кликах и открытии меню.

### P2 — функции скрыты, но не удалены

`app/main.swift:178,465,801`: ConfigStore, SettingsView и buildLegacyMenu сохранены; VPN, сетевой профиль, бенчмарк и обработчики остаются. JSON по-прежнему опрашивает VPN-состояние. Это не соответствует запросу «лишние фичи выпили» и сохраняет лишние зависимости/работу в фоне.

Критерий исправления: удалить неиспользуемый UI и его обработчики. Отдельно определить миграцию ранее установленных VPN/net-демонов: просто удалить управляющий код недостаточно, уже установленная автоматика продолжит существовать.

### P2 — версия UI может работать с несовместимым CLI

`app/main.swift:79`: установленный CLI приоритетнее вложенного, но новая версия UI требует enable/disable и поле enabled. Старый CLI без поля enabled будет отображаться как выключенный; неизвестные команды не дадут видимой ошибки из-за потери exit code.

Критерий исправления: версия/возможности CLI проверяются либо используется согласованная вложенная версия.

### P2 — установка и сайт обещают другой сценарий

`docs/index.html:499,560,566`: сайт описывает ручные режимы, Settings и ручную настройку системного прокси. `make-dmg.sh` обещает автоматический поиск при запуске и отключение автозапуска через уже отсутствующее меню. `install.sh` меняет сеть на этапе установки. В нижней части README остаются инструкции про VPN в Settings.

Критерий исправления: единое описание «установить → открыть меню → настроить и включить → выключить» во всех точках входа.

## Референсы Mobbin

Mobbin MCP подключён через `https://api.mobbin.com/mcp`, OAuth завершён, поиск экранов и flows выполнен успешно. Изображения результатов просмотрены. Это iOS-референсы композиции и обратной связи; они не заменяют нативные паттерны меню macOS.

- [Opera — статус VPN](https://mobbin.com/screens/d535f3b2-da66-427c-92d7-b679c7dede17): крупный центральный статус и отдельное действие Disconnect. Для ProxyPilot подходит иерархия «состояние → одно действие». Щит и обещание безопасности переносить нельзя: локальный proxy bridge не гарантирует VPN-защиту.
- [Opera — Turning on VPN](https://mobbin.com/flows/c542374c-7ef4-4d9d-9144-ef6a49c3d387): flow из шести экранов; просмотрены возвращённые превью 1, 4 и 6. Видны исходный Disabled, выбор региона и итоговый Protected / Disconnect. Полезен переход к ясному итоговому состоянию; выбор региона ProxyPilot не нужен.
- [NordVPN — отключение и пауза](https://mobbin.com/screens/4866f93d-811c-4bc1-a4b4-b4daf178f860): статус Secured, меню длительностей паузы и Disconnect. Для нашего сценария лишние варианты паузы увеличивают выбор; использовать только ясное именование отключения.
- [Base — подключение](https://mobbin.com/screens/ae8e2310-7bdb-4de6-8695-296666922d6e): явное Connected и Disconnect, но дополнительный CTA и иллюстрация интеграции делают его менее подходящим.

Рекомендуемая композиция: компактная панель с названием, одной строкой состояния, коротким пояснением при необходимости и одной основной кнопкой. При выключении — «Включить», при успехе — «Выключить», при неудаче — «Повторить». Маршруты, IP, тип прокси и логи не нужны в нормальном состоянии. Не обозначать «включено» как «защищено».

## Следующая проверка перед выпуском

После исправления P1 пройти на тестовой macOS-машине: чистую установку; успешный/неуспешный поиск; отказ разрешения Local Network; включение; выключение; выход при включённом прокси; повторный запуск; новый и существующий терминал; смену сети; сон; перезагрузку. На каждом шаге сверять видимый статус с реальными HTTP/HTTPS-запросами и системными настройками. Затем проверить читаемость, фокус клавиатуры и VoiceOver.

В этой итерации код продукта не исправлялся: результат — диагностика, воспроизведения и референсы.

## Повторная попытка пройти установленное приложение на Mac

После отдельного запроса пользователя выполнить проход кликами проверено живое окружение:

- Запущен `/Applications/ProxyPilot.app/Contents/MacOS/ProxyPilot`; установленный бинарник имеет дату изменения 4 сентября, то есть предшествует текущим изменениям минимального меню.
- Мост действительно запущен в режиме direct. Системные HTTP и HTTPS proxy включены и направлены на 127.0.0.1:3129. Это исходное состояние, а не результат клика во время теста.
- Выбор приложения по bundle ID обнаружил две копии: установленную и `app/build/ProxyPilot.app`. Выбор точного установленного пути вернул timeout.
- Обычное окно Finder доступно: дерево интерфейса и его снимок получены. Выбор SystemUIServer также вернул timeout. Попытка фокусировать значки меню клавиатурой не дала доступного интерфейса ProxyPilot.
- Настройки сети и запущенная установленная копия во время этой попытки не менялись. On/off/quit кликами ещё не пройдены. Для следующей попытки нужен открытый пользователем popup меню ProxyPilot; если он станет доступен автоматизации, можно продолжить и затем отдельно проверить свежую сборку.

Следовательно, эта попытка подтверждает ограничение доступа инструмента к menu-bar приложению, но не подтверждает исправность или неисправность пользовательских кликов.
